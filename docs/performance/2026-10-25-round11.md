# Lazy timeline measurements, eleventh round

Measured on 2026-10-25 against Ruimte `b9ce6b8b6` and ADE CORE `628990a9`, with Bun 1.4.2, macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round11.json) include three fresh headless Chromium profiles per version, five 90-step scroll bursts per profile, and separate CPU-profile summaries. The fixture renders the production chat timeline with 30,000 cached user messages. Canvas rendering is excluded.

## Retained change

The timeline projected every message tick into an array of measured positions on every render. The installed virtualizer exposes a lazy measurement view: reading an entry materializes its measurement object. That projection forced thousands of offscreen entries into objects on every scroll update. A separate two-burst CPU profile attributed about 1.57 seconds of self time to the projection callback alone.

The reading-position helpers now accept the native `length` and `at` interface. Existing arrays still satisfy it. The timeline supplies a view that reads a measurement only when a binary search or message-navigation step requests it. It reads current measurements, so row-height changes remain visible without a separate position cache.

| Measurement | Before | After |
| --- | ---: | ---: |
| Main-thread task time per 90 scroll steps, median of 15 bursts | 1,645.57 ms | 744.48 ms |
| Range of profile medians | 1,637.0 to 1,660.1 ms | 740.2 to 744.7 ms |
| Animation-frame step interval, median across 1,350 steps | 24.2 ms | 16.4 ms |
| Animation-frame step interval, 95th percentile | 31.2 ms | 26.2 ms |
| First settled timeline render, median of three profiles | 119.9 ms | 100.9 ms |

The repeated scroll uses about 55 percent less main-thread CPU. These are renderer measurements with the history already cached. They exclude network loading, Electron startup and physical display behavior; frame intervals in this synthetic headless loop are not a display-FPS guarantee. Cold rendering is a smaller three-profile sample.

## Validation

Every browser profile checks that the item being read stays at the same pixel offset when 90 older messages are prepended. It also appends while reading and while following the end: the reading offset stays, and following ends with a zero-pixel gap and the last row visible. The number of mounted timeline rows stays bounded.

The new unit test queries a 30,000-position measurement view, permits fewer than 40 position reads, changes its underlying positions and verifies the new visible range and keyboard steps. It failed before the helper change. Existing array, boundary, bookmark and navigation tests still pass.

A 1,000 ms CPU budget for a 90-step burst fails on the previous implementation and passes in all three current browser profiles. CPU profiles run separately from timing batches. The old profile was regenerated through temporary source overrides in the compiler loader, without replacing working files.

The full application check, 10,443 unit tests and client/desktop build pass. ADE CORE's complete check and build pass, with 7,308 tests passing and 286 skipped. The focused position tests pass with 100 assertions.

## Reproduce

```sh
BENCH_ITEMS=30000 BENCH_SCROLL_RUNS=5 BENCH_MAX_TASK_MS=1000 bun --conditions=source apps/client/testing/performance/timeline.ts
```

Run without competing builds or tests. The probe uses the built client styles, compiles the React sources with the same compiler as the application, and removes its temporary page and browser profile afterward.
