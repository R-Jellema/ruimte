# Sidebar rendering and navigation, thirteenth round

Measured on 2026-10-25 against Ruimte `cdcabba9c`, with ADE CORE `7b742950`, Bun 1.4.2, macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round13.json) include old and current production client builds, three fresh headless Chromium profiles per build, and a separate interleaved smaller fixture. Canvas rendering is excluded.

## Retained change

Round five reduced the cost of the sidebar watcher. This round measures the actual application, including React and the browser, against an isolated daemon. The large fixture has 20 open projects with 100 views each, using files and inactive chats. A file is active. Sixty valid `chat.status` frames alternate one chat between idle and needs-you, exercising both its status dot and its appearance in the waiting section. No agent turn runs.

A CPU profile showed repeated React row work and substantial allocation. Per-row focus closures and the arrow-navigation callback changed whenever the list was derived again. The list now handles focus and vertical arrow navigation through its existing container. Rows retain their own actions, rename behavior and horizontal fold keys. Background rows read the values they display before building callbacks and children, so a fresh derived row object does not invalidate unchanged content in the React Compiler's cache. No manual React memoization or additional data cache was added.

| Measurement | Before | After |
| --- | ---: | ---: |
| Main-thread task time for 60 updates, 2,000-view fixture | 4,796.25 ms | 1,342.53 ms |
| Range of profile CPU totals | 4,772.9 to 4,809.8 ms | 1,318.8 to 1,376.5 ms |
| Median two-frame update step, 180 updates per version | 85.1 ms | 32.8 ms |
| CPU for 60 updates, 100-view fixture, four interleaved profiles | 492.24 ms | 471.14 ms |

The large fixture uses about 72 percent less main-thread CPU. The smaller fixture improves slightly and retains the same two-frame pacing. Its first separate batches drifted enough to suggest an 8 percent regression; the interleaved control/current/current/control order did not reproduce that result. Both batches remain in the raw evidence.

These are status-update measurements. They do not measure transport throughput or physical display FPS. The probe intentionally waits two animation frames after each update, so roughly 33 ms is its pacing floor. The workspace already has its content loaded before CPU timing begins.

## Validation and intermediate trial

Reading background-row values alone reduced large-sidebar CPU only about four percent. Sharing navigation at the list made the substantial difference. Both intermediate stages were measured separately before proceeding, and their samples are retained.

Every timed update verifies the corresponding row changed to the expected state. Every final browser profile also checks up/down navigation and a single tab stop in both active and background projects. A separate 2,000 ms CPU budget fails on the old build at 4,941.98 ms and passes in all three current profiles.

Three new DOM tests cover focus, tab stops, active/background arrows, project folding, skipping hidden rows and arrow keys inside a rename field. Existing rename and project-order tests pass. The escaped combined-project row selector now uses an unquoted CSS identifier, which works in Chromium and the DOM test implementation.

The full application check, build, 10,443 unit tests and all 391 DOM tests pass. The probe cleans up its daemon, temporary project files and isolated browser profiles.

## Reproduce

```sh
BENCH_RESTORE_RUNS=3 BENCH_MAX_TASK_MS=2000 bun --conditions=source apps/client/testing/performance/sidebar-render.ts
BENCH_PROJECTS=1 BENCH_RESTORE_RUNS=3 bun --conditions=source apps/client/testing/performance/sidebar-render.ts
```

Set `BENCH_CLIENT_DIST` to a separate old client build to measure a control. The final control was built through a temporary Vite load plugin reading the two saved original source files; working source files were never swapped. Run timing probes separately from builds and tests.
