# Directory listing, ninth round

Measured on 2026-10-25 against `e5fc7d581`, with Bun 1.4.2 on macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round9.json) retain the separate experiments, including rejected work. Each listing batch has nine samples after one warm-up, over real files in an isolated temporary directory.

## Retained changes

Natural filename sorting passed options to `localeCompare` on every comparison. It now reuses one lazily created `Intl.Collator` with the same locale and numeric options. Directories still precede files, numbers sort naturally, and equal names retain the directory enumeration order.

A listing returns at most 2,000 entries across its requested depth. Previously, it read metadata and fully sorted every visible name before applying that limit. It now chooses the retained names first, reads metadata only for those entries, and orders only the required prefix when the directory exceeds the remaining budget. Short directories still use the native full sort. A private heap preserves stable ties through each candidate's original index.

| Real directory listing | Before | After |
| --- | ---: | ---: |
| 1,800 files and two directories, original comparison | 17.42 ms | 5.68 ms with collator reuse |
| Same fixture, final implementation | 16.59 ms in the control rerun | 5.77 ms |
| 10,000 files, returning the first 2,000 entries | 123.98 ms | 20.14 ms |
| 1,800 files inside a Git repository | 97.25 ms | 86.74 ms |

The wide-directory stages isolate the work: collator reuse measured 33.15 ms, selecting names before metadata measured 25.07 ms, a partial heap-ordering trial measured 18.17 ms, and the final specialized version measured 20.14 ms in a subsequent batch. The exploratory 20 ms budget was not consistently met; this is not a stable 20 ms guarantee. The initial 15 ms budget for the smaller non-Git fixture fails on the old implementation and passes on the new one.

Git ignore processing remains part of the real repository fixture and dominates that case. The non-Git gains should not be read as the total saving for every project. All samples have warm filesystem data; they do not simulate a network drive or cold storage.

## Rejected work and validation

An attempt to share a generic heap between directory listing and file search made pure ranking of 100,000 paths roughly 13 to 19 percent slower in several queries. Disk-backed search changed less, but the extraction was rejected. File search retains its previous implementation. Its before/after results matched exactly during the experiment; the raw samples remain for comparison.

The listing tests now check the exact natural-order boundary and the remaining budget in a nested directory, alongside existing coverage of metadata, hidden files, ignored files, nested repositories and symlinks. The listing benchmark checks every returned filename and file size, including truncation. No wire or persistence format changes.

The complete check, 10,439 unit tests with 52,162 assertions, and the client/desktop build pass.

## Reproduce

```sh
git show e5fc7d581:apps/server/src/fs/list.ts > /tmp/list-control.ts
BENCH_LIST_SOURCE=/tmp/list-control.ts BENCH_MAX_LIST_MS=15 bun --conditions=source scripts/performance/file-list.ts
BENCH_MAX_LIST_MS=15 bun --conditions=source scripts/performance/file-list.ts
BENCH_FILES=10000 bun --conditions=source scripts/performance/file-list.ts
BENCH_REPOSITORY=1 bun --conditions=source scripts/performance/file-list.ts
```

`BENCH_FILES` defaults to 1,800 and `BENCH_RUNS` to nine. The runner creates and removes its own files and optional Git repository. Source controls use Bun's loader without replacing working files. Run timing jobs separately from checks, tests and builds.
