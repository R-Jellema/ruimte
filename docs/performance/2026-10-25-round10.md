# Git ignore paths through aliases, tenth round

Measured on 2026-10-25 against `b9ce6b8b6`, with Bun 1.4.2 on macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round10.json) include the initial path-format probe, standalone measurements and an interleaved comparison on the same repository.

## Retained change

The remaining delay in the Git-backed directory fixture came from absolute paths addressed through a directory alias. A direct control found about 73 ms for 1,800 absolute aliased paths, versus about 8 ms for canonical absolute paths or relative paths. Git process startup alone was about 8 ms.

Git's [absolute-path normalization](https://github.com/git/git/blob/master/setup.c) resolves path components when the worktree is not already the absolute prefix. The fixture's alias forces that work for every submitted path. The daemon now checks the working directory once. When it is an alias, absolute paths lexically below it are sent relative to it. Returned names are mapped back to each caller's original paths. Canonical and already-relative queries keep their existing route.

The interleaved fixture creates 1,800 files, ignores one in five, and alternates the order of old and current implementations for nine runs after a warm-up. Both versions operate on the same files with isolated Git configuration and must return exactly the same ignored paths.

| Input form | Before | After |
| --- | ---: | ---: |
| Canonical absolute paths | 8.66 ms | 8.74 ms |
| Absolute paths through a directory alias | 108.12 ms | 9.40 ms |
| Already-relative paths through that alias | 8.21 ms | 8.24 ms |

The Git-backed 1,800-file listing from the previous round measured 86.74 ms before this change and 14.77 ms afterward in separate batches. That fixture uses the macOS temporary-directory alias. This improvement applies to aliased paths, rather than every Git call on the machine.

## Correctness

A generated `./` prefix keeps a filename beginning with a colon from becoming Git pathspec syntax. Directory trailing separators, spaces and NUL-delimited newline names remain intact. Tests cover mixed absolute and relative callers, checkout aliases, tracked files that match an ignore pattern, nested working directories and the existing refusal behavior for outside paths. One intermediate relative-path trial failed the new literal-name test; the retained version passes it. Git still determines every answer, so changes to ignore rules and the index require no application-cache invalidation.

The original alias benchmark failed a 30 ms budget; the retained implementation passes it. The full application check, 10,443 unit tests with 52,168 assertions, and the client/desktop build pass. The focused Git and listing tests also pass.

## Reproduce

```sh
git show b9ce6b8b6:apps/server/src/git/ignore.ts > /tmp/ignore-control.ts
BENCH_IGNORE_CONTROL_SOURCE=/tmp/ignore-control.ts BENCH_MAX_ALIAS_MS=30 bun --conditions=source scripts/performance/git-ignore.ts
BENCH_REPOSITORY=1 bun --conditions=source scripts/performance/file-list.ts
```

`BENCH_PATHS` and `BENCH_RUNS` adjust the ignore fixture. With a source control, versions alternate on one isolated repository; without one, only the current implementation runs. The runner keeps global Git configuration out of the fixture and removes its files and directory alias afterward.
