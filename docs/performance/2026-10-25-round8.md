# Chat reconnect replay, eighth round

Measured on 2026-10-25 against Ruimte `4e1384273` and ADE CORE `19fb7247`, with Bun 1.4.2 on macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round8.json) include Bun and three fresh Chromium profiles per version. Each profile measures seven bursts after a warm-up.

## Retained change

A chat reconnect can receive hundreds of events missed while it was disconnected. `ChatClient` previously applied each separately to the store. Every text delta cloned the chat's whole item dictionary and published another state change before the replay was complete.

The built-in chat sink now accepts an ordered replay batch. It privately copies the item dictionary and reuses that copy until a structural snapshot must be preserved or a reset replaces it. It publishes only the completed state. Single live events continue through the existing immediate path. Custom sinks without the optional `replay` method keep receiving individual events.

| Process 200 missed text events with 6,000 cached items | Before | After |
| --- | ---: | ---: |
| Chromium, range of profile medians | 108.3 to 109.8 ms | 0.7 to 0.8 ms |
| Bun median | 23.36 ms | 0.15 ms |
| Store publications per replay | 200 | 1 |

The fixture executes the production store and sink, checks exact final text, and confirms that the previous snapshot, item order and structural snapshot remain unchanged. It does not mount React. The measurement isolates client processing after the replay has arrived, rather than network latency or total reconnect duration. No event is dropped or merged, and wire bytes are unchanged. A separate live-event control measured profile medians of 108.5 to 109.9 ms before and 110.0 to 112.2 ms after for the same 200-event burst. There is no demonstrated live-event speedup; this small processing increase accompanies the shared reducer path. The retained gain is reconnect replay.

The same headless script runner now serves this benchmark and the sidebar benchmark. A separate sidebar smoke run confirms the existing probe still runs after that harness refactor.

## Validation

The existing cached-history reconnect test now also checks that subscribers receive the completed replay once. It failed on the old implementation, which published the intermediate reply too. Other tests cover custom-sink fallback, checkpoint reuse, eviction during replay, mixed structural events and deltas, query metadata, Unicode tool-output tails, reset handling and special item ids. Old snapshots remain immutable, including across a later replay. Empty replays do not publish another state.

The complete Ruimte and ADE CORE checks, tests and builds pass: 10,439 Ruimte tests and 7,307 ADE CORE tests, with 286 ADE CORE tests skipped. A separate 6,000-item browser timeline check retains the same item at the same pixel offset after prepending history, keeps the reading offset during append, and follows the final row with no gap when at the end. It is a correctness check, not a scrolling speed comparison. ADE CORE's documentation describes the optional method and is built separately. Browser timing jobs run without competing builds or tests.

## Reproduce

```sh
BENCH_MAX_REPLAY_MS=20 bun --conditions=source apps/client/testing/performance/chat-replay.ts
git -C ../adecore show 19fb7247:packages/agents-react/src/state/chats.ts > /tmp/chats-control.ts
BENCH_CHATS_SOURCE=/tmp/chats-control.ts bun apps/client/testing/performance/chat-replay-browser.ts
```

`BENCH_ITEMS`, `BENCH_UPDATES` and `BENCH_RUNS` change the fixture. `BENCH_LIVE=1` measures individual live-event application instead of replay. `BENCH_PROFILES` sets the number of fresh browser profiles, three by default. The scripts remove their temporary files, isolated profiles and local server afterward.
