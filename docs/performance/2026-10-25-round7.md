# Chat request indexing, seventh round

Measured on 2026-10-25, Ruimte `371f69212` and ADE CORE `4690b60e`, with Bun 1.4.2 on macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round7.json) contain nine runs per case after one warm-up. Canvas rendering remains outside the investigation.

## Retained change

`ChatThread.pending()` mapped and filtered every item in a chat whenever request summaries or the waiting status were recomputed. Updating one approval in a long conversation repeatedly visited thousands of unrelated messages. Replaying stored request events did the same work while reopening the chat.

The thread now indexes only pending approvals and questions. It updates that index on construction, item replacement and reset. Pending requests are returned in their original thread order, including after an earlier request is closed and reopened. Status checks use the index size. Neither the persisted format nor the wire protocol changes.

| Measurement | Before | After |
| --- | ---: | ---: |
| 30,000 items, 200 request updates plus status and pending reads | 140.83 ms | 0.14 ms |
| 30,000-item stored snapshot plus 200 request events, `ChatStore.read` | 55.12 ms | 10.21 ms |
| 6,000 items, same request updates | 25.05 ms | 0.12 ms |
| 6,000-item stored chat, same event log | 10.88 ms | 2.81 ms |

The synthetic history contains one completed approval per ten items. The event log alternates one live approval between pending and allowed. Every update checks the expected status and pending count. The restore probe reads and validates a real stored snapshot and log, checks the resulting item count, and rejects a stale pending summary. File data is warm in the operating-system cache. These numbers measure daemon state processing and record restoration, not total screen rendering or a person's disk speed.

The comparison for the smaller case uses Bun's source loader to read the original `thread.ts` from ADE CORE `4690b60e`; no working files were swapped. The initial 30,000-item comparison was measured before editing the implementation. A 20 ms processing budget fails before the change and passes afterward.

## Validation

Tests cover ordering after reopening a request, mixed approvals and questions, stored reconstruction, history boundaries, reset replay and status changes. Replacing a request with another item kind now also clears its summary; the new test for that case failed before the fix.

The full Ruimte check, 10,439 unit tests and client/desktop build pass against the linked ADE CORE source. The benchmark is separately typechecked with the server's compiler options. ADE CORE's complete check and build pass, with 7,305 tests passing and 286 skipped. Its test run was repeated after the build completed because the first parallel attempt read compiled exports while they were being rebuilt.

## Reproduce

With the linked ADE CORE checkout:

```sh
BENCH_MAX_UPDATES_MS=20 bun --conditions=source apps/server/scripts/performance/chat-thread.ts
BENCH_ITEMS=6000 bun --conditions=source apps/server/scripts/performance/chat-thread.ts
```

`BENCH_ITEMS` and `BENCH_RUNS` must be positive integers; `BENCH_UPDATES` must be positive and even. The runner defaults to 30,000 items, 200 updates and nine samples, and removes its temporary stored chat afterward.
