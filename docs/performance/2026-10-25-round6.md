# Daemon CLI readiness, sixth round

Measured on 2026-10-25 against `cef611c01`, with Bun 1.4.2 on macOS 27.2 and an Apple M4 Max. [Raw samples](2026-10-25-round6.json) include an initial experiment, the checked-in reproduction and a normal-start control. Every timing batch has nine runs with isolated daemon data. The first execution of each new compiled file is warmed separately; operating-system file validation is outside these boot measurements.

## Retained changes

The daemon started a `codex --help` capability probe beside its store loading, then awaited it while wiring all agents. An external CLI that took longer than the rest of boot delayed every client connection, even when nobody launched a Codex terminal. A hung CLI could hold boot until the five-second probe timeout.

The probe still starts early. Its result is now awaited only before constructing a Codex terminal's first command or resume command. The capability check preserves the version-dependent `--no-daemon` flag, which prevents Codex's shared server from borrowing another terminal's hook environment. Plain shells, other agents, project lists and restored shells can proceed while it runs. A pending help process is aborted when the daemon exits.

| Spawn to authenticated connection and first project list | Before | After |
| --- | ---: | ---: |
| Controlled 300 ms CLI probe, reproducible runner | 390.82 ms | 85.76 ms |
| Normal boot, no installed Codex in the benchmark environment | 82.51 ms | 84.21 ms |

These medians show removal of an external prerequisite from the daemon's critical path. They do not imply a 305 ms saving on every machine: a probe already complete by the time agents are wired costs no waiting. Normal boot is effectively unchanged in this batch. The controlled probe replaces only the help callback; the daemon binary, local-secret proof, ticket, WebSocket protocol handshake and project-list request are real.

The slow-boot experiment also exposed a race: provider discovery emitted an endpoint event before the closed-lid and network services were bound, which terminated the daemon. The provider-change listener now attaches after all identity bindings exist. To measure the waiting cost independently, both benchmark versions receive this same listener-order correction. The untouched baseline failed before measurement with `The closed-lid rule of the machine identity was used before the daemon handed it over`.

## Validation

The readiness tests failed on the previous implementation because commands were already spawned or resumed. They now verify that only the affected CLI waits, duplicate resumes are refused, a shell that exits receives no command, an agent that starts reporting again receives no second resume, and a restored shell opens without waiting. The resume path rechecks the live-agent guard after asynchronous preparation.

The full check, 10,439 unit tests and client/desktop build pass. Four real-PTY terminal-stream integration tests pass with 31 assertions. Existing launch tests retain coverage of supported and unsupported Codex flags and probe timeout behavior.

## Reproduce

Run the timing jobs separately from builds and tests:

```sh
BENCH_RUNS=9 BENCH_CONTROL_REF=cef611c01 BENCH_MAX_STARTUP_MS=200 bun --conditions=source scripts/performance/daemon-cli-probe.ts
BENCH_RUNS=9 BENCH_MAX_STARTUP_MS=200 bun --conditions=source scripts/performance/daemon-cli-probe.ts
```

The first command prints its samples and fails the 200 ms budget; the current implementation passes. `BENCH_PROBE_DELAY_MS` sets the controlled help latency and defaults to 300. The runner compiles into its own temporary directory, warms the executable once, runs the existing local-startup probe and removes its binary and fixtures afterward. It neither installs a CLI nor touches the running application.
