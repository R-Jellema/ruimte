# Routines

The invariants of this folder. The repository root's `CLAUDE.md` has the map, the wire protocol and the rules that hold everywhere, including the work the daemon schedules on a clock; the outbox entry is in `apps/server/src/outbox`.

- A routine is work that starts once at a set time or on repeat, in one project: an agent with a prompt, a command in a shell, or a launch of the project. Its definition lives in `.ruimte/routines.json` (shared, a team commits it) or `.ruimte/private/routines.json` (one person's), and the private file also keeps per routine what is one person's on this machine: the account, a pause, a refusal (`local`). A routine entry this release cannot read is kept and written back as it stands.
- A routine runs only as a person on this machine approved it as it stands now: its digest (`digestOf`) under `$RUIMTE_HOME/command-approvals` with the key `routine:<id>`. A person's `routine.save` approves what it writes; a verb, git, a hand edit or anything else never does, so a change from any of them asks again. An agent's save is narrowed to its own mode ceiling first, and the chat that made it is written down under `$RUIMTE_HOME/routine-authors` for the approval card.
- A routine runs whether a client has its project open or not, for every project the machine's register knows; pause is how a person stops it. A removed project runs nothing.
- Each routine is owed at most one `routine-run` entry, due at its next time. The handler reads the files from disk again, so a change that came in while nobody watched decides. A time that passed while the machine slept or was off is run once on wake, as `caught-up` with the times it missed, never once per time. A run whose previous one still runs or waits on a person is written down as `skipped` and never queued. Resuming owes the next time from now. Daylight saving goes by the wall clock of the machine's time zone: a skipped time runs after the skip, a doubled one runs once.
- An agent run is a hidden agent chat of the project, opened by `routine:<id>`, started through the outbox as `start-agent` does, with the person's mode as its ceiling; it is on no canvas, and it outlives its routine. Its brief tells it to publish to Output under the routine's output key; the daemon gives a version published from that chat `maker: 'routine'` with the routine and run from its own record (`provenanceOf`). A command or launch run delivers what it printed as a version itself (`Artifacts.deliver`).
- Removing a routine never removes its runs, their chats or its artifact.
- A routine node (kind `routine`) holds only the id of a routine of its own project (`routine`, the last field of `ProjectNodeSchema`), and that id travels in the shared file, unlike an artifact's reference: a shared routine's id names the same routine for a teammate, a private one's names nothing on their machine, and the node says it is not there. A Ruimte older than the kind reads the node as `unknown` and writes its entry back as it was (`project-split.test.ts`). The node draws from the client's routine list and asks the machine nothing of its own; a block of its strip opens that run in Routines, since a run's chat is hidden and on no canvas. `read` of the node prints the routine and its newest runs (`routine-report.ts`); `node new routine --routine` adds one, and approves nothing.
- A launch routine starts a launch only as an agent would: when a person approved that launch as it stands now.
- An agent reaches routines only through `ruimte-context routine` (`canvas/routine-verb.ts`, handled in `actions/routine-actions.ts`, through `agent-host.ts`): it lists, adds, edits, pauses and resumes the routines of its own project, and runs one now only when a person approved it as it stands (`routine-held` otherwise, `routine-busy` while its previous run goes on). Every add or edit goes through `saveByAgent`, so it waits on a person again. There is no verb that approves, declines or removes a routine.
