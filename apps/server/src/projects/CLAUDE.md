# Project, drawing and diagram files

The invariants of this folder. The repository root's `CLAUDE.md` has the map, the wire protocol and the rules that hold everywhere, including the two project files and who closes a project.

- A drawing or diagram file follows its view between `.ruimte/<kind>s/` and `.ruimte/private/<kind>s/`, so a private drawing never sits in git either.
- A project file whose `version` is newer than this build is refused (`project-too-new`) and left untouched, never set aside as `.corrupt`. Same for a drawing and a diagram.
- A project is held by the clients that have it open (`ProjectHolds`), for as long as their socket lives. Only they hear `project.changed`; every other client hears a change of the document as `project.summary` with its sidebar rows (`announceChange`). `closedAt` in the registry is the machine's own fact, which the sidebar an agent reads is filtered on.
- Closing (`ProjectStore.closeProject`) ends the sessions the project's document holds, read off the index, so a project nobody has on screen closes the same way.
- The private file's `overlayFields` names the node fields a newer Ruimte keeps one person's. `mergeFiles` returns them (declared ones plus any unknown key found in the overlay), `OpenProject` remembers them, and every write hands them to `splitContent`, so a save, a verb and an outside edit all put those fields back in the overlay and never in the shared file.
- Which node runs on another machine lives in `RemoteStore` under `$RUIMTE_HOME/remote`, never in a project file. `ProjectStore` lays it over a document as `machine` only where it goes out (open, `project.changed`) and keeps the index and every verb without it. A save that names none leaves the binding; a node that leaves the document takes it along; a verb's change keeps the machines the store holds and drops any other.
- A canvas a machine keeps for another machine's nodes is `hidden` the same way: the daemon lays it over the document, `splitContent` and `mergeFiles` drop it from both files, and a save that shares one is refused (`hidden-view-shared`). A hidden chat view is stored.
- A save binds a node to another machine only for a terminal, chat or device node that has started nothing on this machine (no live session, chat record or lineage), never to this machine's own id, and never to a different machine than the one it is bound to (`remote-node-invalid`).
