# Language servers

The invariants of this folder. The repository root's `CLAUDE.md` has the map, the wire protocol and the rules that hold everywhere; `apps/server/README.md#language-servers` has the kinds, install locations and pins.

- The daemon is the one owner of a document's text and version. A change whose `baseVersion` is not the daemon's is refused as `stale-document`, and the client opens the document again whole. A path is a stored path and goes through `MachineHome` like `fs.read`.
- A document opens on every kind that serves it (`SharedDocument.kinds`, its language's kind first); `eslint` and `tailwind` join only in a project that calls for them (`activation` in `profiles.ts`). Completion, code actions and hover merge across servers (`merge.ts`); any other feature is the first server's that offers it.
- The first server of a merged call is awaited without a deadline; every other one gets `MERGE_DEADLINE_MS` and is left out after it, so a slow addition never holds up the main server. A server that does not answer `initialize` within `INITIALIZE_TIMEOUT_MS` is ended and marked `crashed` (`server.ts`). These timers belong to a request under way and schedule nothing.
- TypeScript 7 lacks most quick fixes and every refactor, so the `typescript` kind runs a TypeScript 6 sidecar (`typescript-actions`) that starts lazily on the first code action, is asked only for its own actions and has its diagnostics dropped. It waits `SIDECAR_START_DEADLINE_MS` on the first request and `MERGE_DEADLINE_MS` after.
- Vue stays on TypeScript 6, since TypeScript 7 has no plugin API: in a Vue project the scripts go to the `vue` kind so only one tsserver runs. A project's own TypeScript wins over the pinned one when it is new enough (`ownNativeTypescript` in `profiles.ts`).
- A process that ends by itself after `STABLE_AFTER_MS` of being ready is started again once, on the exit event; any other end is `crashed` until `language.restart`. Every process of a pair goes down and comes up together, and its diagnostics are cleared while it is down.
- File watching starts only once a server registered for `workspace/didChangeWatchedFiles` (`file-watch.ts`) and ends with the last such server. Events settle in the watch seam's timer and go to each server filtered by its own patterns; nothing runs on a clock of its own.
- A server's `workspace/applyEdit` goes to the client that ran the command (`language.edit`), never applied by the daemon, and is refused when no command of that client runs or it stays silent 30 seconds. Rename edits from `workspace/willRenameFiles` follow `fs.create` and `fs.write` rules.
- An agent uses the servers through `AgentLanguage` (`agent-language.ts`) as a client of its own for one call. It never installs a server, and a file read against a connection agents may not use is refused whole (`database-access-off`).
- A native server never fetches anything itself: Install downloads PHP's stubs, and the server starts with `storagePath` and `stubsPath`. Checkout discovery reads files and never runs a git command that changes anything.
