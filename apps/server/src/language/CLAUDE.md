# Language servers

The invariants of this folder. The repository root's `CLAUDE.md` has the map, the wire protocol and the rules that hold everywhere; `apps/server/README.md#language-servers` has the kinds, install locations and pins.

- The daemon is the one owner of a document's text and version. A change whose `baseVersion` is not the daemon's is refused as `stale-document`, and the client opens the document again whole. A path is a stored path and goes through `MachineHome` like `fs.read`.
- A document opens on every kind that serves it (`SharedDocument.kinds`, its language's kind first); `eslint` and `tailwind` join only in a project that calls for them (`activation` in `profiles.ts`). Completion, code actions and hover merge across servers (`merge.ts`); any other feature is the first server's that offers it.
- The first server of a merged call is awaited without a deadline; every other one gets `MERGE_DEADLINE_MS` and is left out after it, so a slow addition never holds up the main server. A server that does not answer `initialize` within `INITIALIZE_TIMEOUT_MS` is ended and marked `crashed` (`server.ts`). These timers belong to a request under way and schedule nothing.
- TypeScript 7 lacks most quick fixes and every refactor, so the `typescript` kind runs a TypeScript 6 sidecar (`typescript-actions`) that starts lazily on the first code action, is asked only for its own actions and has its diagnostics dropped. It waits `SIDECAR_START_DEADLINE_MS` on the first request and `MERGE_DEADLINE_MS` after.
- Vue stays on TypeScript 6, since TypeScript 7 has no plugin API: in a Vue project the scripts go to the `vue` kind so only one tsserver runs. A project's own TypeScript wins over the pinned one when it is new enough (`ownNativeTypescript` in `profiles.ts`).
- A process that ends by itself after `STABLE_AFTER_MS` of being ready is started again once, on the exit event; any other end is `crashed` until `language.restart`. Every process of a pair goes down and comes up together, and its diagnostics are cleared while it is down.
- File watching starts only once a server registered for `workspace/didChangeWatchedFiles` (`file-watch.ts`) and ends with the last such server. Events settle in the watch seam's timer and go to each server filtered by its own patterns; nothing runs on a clock of its own.
- Each server runs one client command at a time because LSP does not tie `workspace/applyEdit` to its originating command. The edit goes to that command's client (`language.edit`), never applied by the daemon, and is refused when no command of that client runs or it stays silent 30 seconds. Rename edits from `workspace/willRenameFiles` follow `fs.create` and `fs.write` rules.
- An agent uses the servers through `AgentLanguage` (`agent-language.ts`) as a client of its own for one call. It never installs a server, and a file read against a connection agents may not use is refused whole (`database-access-off`).
- Work another machine sent (`UntrustedFolders.inFolder`, a project folder in it or a document in it) gets no kind that runs project code (`runsProjectCode`: rust-analyzer, ESLint, Tailwind) and no server of a person's own, and a project folder in it runs the pinned TypeScript, never its own.
- A package set (`packages/<setId>`, `package-store.ts`) is immutable and shared: an install only links its `node_modules` to it, and nothing writes into a set after it is published. Mutable storage (Intelephense's `storage`, caches) stays in the install's own folder. Removing an install goes through `removeInstallFolder`, which unlinks `node_modules` before `rm`, so a removal never reaches into a set. A set goes only through `PackageStore.collect`, which removes what no install on disk refers to and no lease holds, and nothing when the disk cannot be read in full. A dangling link reads as not installed, and Install repairs it. Adoption of real `node_modules` trees runs in `load()` before any server starts and replaces a tree with a link only after every file proved identical.
- Ruimte reads the PHP server's owner manifests (`owner-*.json` in `storage/cache`) and never derives a cache file name. A pass over those caches (`php-cache.ts`) runs inside `StorageGate.hold`, and a `php-native` start awaits the gate first (`beforeSpawn`), so no PHP server starts during a pass. A pass never removes the cache of a folder a server is live in (`LanguageServer.live`, from the start of a start until every process exited), nothing when a manifest is of an unknown format, and files without a manifest only while no PHP process runs. A checkout counts as vanished only after repeated `ENOENT` sightings over a week with no known project folder around it; any other probe result forgets them.
- A native server never fetches anything itself: Install downloads PHP's stubs, and the server starts with `storagePath` and `stubsPath`. Checkout discovery reads files and never runs a git command that changes anything.

## Product rules

Decisions the code cannot show. Do not reverse one without asking Bas.

- Language servers are installed, updated and set back to their previous version only when a person presses Install, Update or the previous version, and never by an agent or a verb. A pin that moved with an update of Ruimte never stops a server: it runs what it has until a person updates.
- The daemon runs them itself, one per project per kind, shared by every client of the project. A server that ends by itself after it had been ready for a minute is started again once at once (the decision is made on the exit, never on a timer), while one that ends sooner, or the one it started again ending within that minute, stays crashed until a person restarts it.
- A server starts with the first document that needs it and ends only when its project closes on the machine (or the daemon stops), so moving between files never restarts it.
- A server of a person's own (a command they typed) is saved only through a request of the local secret, which approves exactly that command, arguments and environment, and lives under `$RUIMTE_HOME`, never in a project file; no verb or agent adds or changes one.
